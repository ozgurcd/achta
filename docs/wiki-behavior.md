## Before, after, consumer adoption

1. Scope: new fixture initially failed `flag provided but not defined: -repo`,
   exit 2. `wiki check` now supports repeatable --repo NAME and
   --exclude NAME=REASON, with explicit NOT judged pages and reasons, including
   when a selected check fails. Proof: "PASS selected freshness; NOT judged broken
   with reason; derive still fails; malformed scopes exit 2". Consumers replace
   external filtering with these flags; callers still decide which pins moved.
2. Freshness: the behind fixture initially reported `exit=0 want=1`, status drift.
   Default `wiki freshness --repo NAME` now enforces exit 1, like wiki check;
   --strict remains accepted. --report-only labels mode report_only and retains
   drift. Proof: "PASS behind page: default exit 1; report_only exit 0 with drift
   retained". Unavailable evidence stays exit 2 even in report mode. Consumers
   use freshness for enforcement and explicitly request non-enforcing reports.
3. Derive: the claim that only wiki check was read-only was false. Installed
   v0.5.9 --check exited 1 with bytes_unchanged=True. Bare derive exited 0 with
   bytes_changed=True. Its preview named stale pages but showed no replacement,
   failing the new preview assertion. Bare derive and --check now preview exact
   before/after content without writing; --write applies and names updated pages.
   Proof: "PASS preview changes no byte; header names Achta version; --write names
   updated page". Another test compares preview bytes with originals and actual
   writes. Consumers add --write to intentional regeneration calls.
4. Header: installed v0.5.9 said "Generated by `wiki/tools/wiki-derive.sh`".
   New blocks say "Generated by achta v0.5.9" in this source build, using the
   source version constant. The header proof rejects the retired name. Consumers
   regenerate once after reviewing a preview. Future version bumps also change
   the generated producer header.
5. Pin: red proof retained updated:2026-09-01 while advancing verified and changing
   DERIVED Repo HEAD. Now only verified_against, verified and updated advance
   (updated is inserted if absent). Proof: "PASS pin and both dates advance;
   DERIVED and lead bytes identical (LF and CRLF)". Existing malformed-page,
   HEAD and review-attestation checks remain. Lead text already survived on old
   code: that reported subclaim was not reproduced. Output says "A new front lead
   is the PM's to write; lead text and DERIVED content are unchanged." Consumers
   write lead prose themselves and regenerate derived facts separately.
6. Order: installed v0.5.9 accepted four reordered lines with status pass,
   violations:[], missing_expected:[], exit 0. --expect-order was initially unknown
   (exit 2); it now evaluates order as expected-order (exit 1).
   Proof: "PASS identical membership reordered exit 1; original order exit 0".
   Consumers require `recipe check --expect-file PATH --expect-order`. This is
   ordered subsequence matching, each occurrence once; extra lines still undergo
   every neutralizer check. Membership-only defaults are preserved.
7. Wiki selection: no routing defect reproduced at this head. Shared resolution
   selects the canonical wiki parent's workspace for all handlers. The fixture
   runs from another valid workspace and proves pin, derive --write and decision
   writes leave ambient wiki bytes unchanged. Proof: "PASS --wiki-dir pin and
   decision writes and derive reads select the requested wiki from another
   workspace". Global --wiki-dir must precede the command and still selects
   WORKSPACE/wiki; no detached-directory support is introduced.

All five changed command help surfaces describe flags, side effects and exits.
Unknown, empty, duplicate and conflicting repository selectors exit 2 before
judgement. Scope does not change the meaning of any selected predicate.

## Open and adjacent

Exclusion reasons are caller assertions, not proof of which commit moves a pin.
A scoped pass makes no claim about omitted repositories. Generated facts still
reflect the live tree and local Git state; preview and write may differ if facts
change between calls. Writes remain atomic per page, not transactional across
pages; a later error may follow earlier successful writes. Pin still requires a
structurally valid DERIVED block even though it does not edit it; dropping that
precondition would change an existing check. Lead prose and sources metadata
remain owner responsibilities. Recipe parsing stays physical-line based, not
Make expansion or shell analysis; ordered subsequence matching allows extra
lines. Consumers must adopt the flags after a separately authorized release.
